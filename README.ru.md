# VDL — Virtual Desktop Launcher

[English](README.md) | Русский

VDL (Virtual Desktop Launcher) — консольная утилита для Windows: перенос окон приложений между виртуальными рабочими столами, запуск приложений на выбранных столах, создание и очистка столов, сохранение и восстановление их расположения.

Для работы с виртуальными рабочими столами Windows используется [библиотека VirtualDesktop от Slion](https://github.com/Slion/VirtualDesktop), доступная в пакете NuGet `Slions.VirtualDesktop`. Спасибо её авторам и сопровождающим за эту возможность.

## Выпуски

[Скачать последнюю версию VDL.exe для Windows x64](https://github.com/statprograms/VDL/releases/latest/download/VDL.exe)

Переносимый автономный исполняемый файл: отдельная установка .NET не требуется. Скачайте `VDL.exe` из файлов выпуска и запускайте его из терминала.

## Быстрый старт

В примерах предполагается, что `VDL.exe` доступен через `PATH` либо находится в текущем каталоге. В PowerShell используйте `./VDL.exe`, если программа не добавлена в `PATH`. Команды изменения рабочих столов выполняют реальные действия. Замените пути к приложениям, идентификаторы процессов и имена файлов значениями для своего компьютера.

```cmd
VDL list --verbose
VDL move-left --title-start "Total Commander"
VDL move Work --process notepad --create --switch
VDL move-all Notes --process notepad --create
VDL run-sole notepad.exe
VDL profile save workspace.json
VDL --help
```

В командах запуска путь к приложению указывается **перед** необязательным целевым рабочим столом:

```cmd
VDL run notepad.exe Work --create
```

## Важно: заголовок терминала может совпасть с условием поиска

Заголовок окна — изменяемый текст. Приложение может менять его при открытии документа, смене каталога, подключении к серверу или выполнении команды. Поэтому терминал иногда попадает в результаты поиска, предназначенного для другого приложения.

Допустим, Total Commander находится на рабочем столе 2, а вы вводите следующую команду в CMD, открытом внутри Windows Terminal:

```cmd
VDL move-left --title Commander
```

Во время работы VDL заголовок видимого окна терминала может стать таким:

```text
C:\WINDOWS\system32\cmd.exe - vdl move-left --title Commander
```

И этот заголовок, и `Total Commander (x64) 11.58` содержат `Commander`. Параметр `--title` ищет подстроку, поэтому оба окна проходят текстовый фильтр. Более длинная фраза создаёт ту же неоднозначность:

```cmd
VDL move-left --title "Total Commander"
```

CMD может включить `"Total Commander"` в свой заголовок вместе с выполняемой командой. Кавычки объединяют слова в один аргумент, но не делают поиск точным и не ограничивают его началом заголовка.

Режим Balanced, используемый по умолчанию, может завершить поиск после стабилизации подходящего основного окна. Среди полученных кандидатов VDL сначала предпочитает окна текущего рабочего стола, а затем учитывает их оценку. Поэтому подходящий терминал может быть выбран раньше нужного приложения на другом столе. Параметр `--all` может выбрать оба окна, а `--single` — отклонить поиск при обнаружении обоих. Ни один из них сам по себе не уточняет, какое приложение вы имели в виду.

В отчёте видно, какое окно выбрала VDL:

```text
Window 1116198 "C:\WINDOWS\system32\cmd.exe - vdl move-left --title Commander" [visible] ->
                            Desktop 1
```

В этом примере выбран терминал. Сообщение `Done` относится к операции над выбранным окном и не означает, что был перенесён Total Commander. После завершения VDL заголовок CMD может снова стать `C:\WINDOWS\system32\cmd.exe`, скрыв временное совпадение.

Если заголовок приложения начинается с известной фразы, используйте поиск по началу заголовка:

```cmd
VDL move-left --title-start "Total Commander"
```

Этот фильтр принимает `Total Commander (x64) 11.58` и отклоняет заголовок с командной строкой, начинающийся с `C:\WINDOWS\system32\cmd.exe`. Результат не зависит от того, удалось ли распознать и исключить запускающий терминал.

Если важна принадлежность окна приложению, а не текущий заголовок, используйте фильтр процесса:

```cmd
VDL move-left --process TOTALCMD64
VDL move-left --process TOTALCMD64 --title-start "Total Commander"
VDL move-left --pid 29184
```

Приведённый PID — пример. Актуальный идентификатор можно найти командой `VDL processes`. Имя процесса тоже проверяется по вхождению подстроки. PID определяет один процесс, но у него может быть несколько окон.

Другой способ ограничить поиск началом строки — регулярное выражение с якорем:

```cmd
VDL move-left --title-regex "^Total Commander\b"
```

VDL пытается исключать из автоматического поиска собственную консоль и видимое окно Windows Terminal, если его удалось определить при запуске. Разные способы запуска терминала и изменения фокуса могут помешать распознаванию. Не полагайтесь на это исключение для устранения неоднозначности фильтра. Явный фильтр процесса или PID позволяет намеренно выбрать терминал.

То же относится к Блокноту, браузерам, редакторам и другим названиям приложений в командной строке. В сценариях предпочитайте `--title-start` или фильтр процесса. Начало строки должно соответствовать реальному заголовку: если редактор начинает заголовок с имени документа, понадобится другая начальная фраза или фильтр процесса.

## Синтаксис команд и выбор окон

```text
VDL <command> [arguments] [switches]
VDL profile <save|load> <file> [switches]
```

- Позиции рабочих столов нумеруются **с единицы**: `1` — первый стол. Аргумент только из цифр трактуется как позиция, даже если один из столов так называется.
- Другие явные цели сопоставляются с именами столов. Имена с пробелами заключайте в кавычки: `"Office 2"`.
- По умолчанию регистр не учитывается. Команды запуска и переноса поддерживают `--case`.
- Без фильтров выбора окна обычные команды переноса используют активное окно. Если вводить команду в терминале с фокусом, активным может быть сам терминал.
- Фильтры ищут подходящие окна на разных рабочих столах. Окно другого стола может быть скрыто DWM (cloaked), сохраняя стиль видимого окна.
- По умолчанию перенос с фильтром выбирает одного кандидата. `--all` выбирает все совпадения; `move-all` подразумевает этот режим.
- Фильтры процессов и заголовков объединяются логическим И. Если одновременно заданы `--title`, `--title-start` и `--title-regex`, должны выполняться все три условия.
- Для команд запуска фильтр исполняемого файла обычно формируется из `ApplicationPath`. Явный фильтр заменяет этот вариант по умолчанию, поэтому задавайте его достаточно точно.
- Запущенное приложение может использовать существующий процесс или окно. VDL ищет подходящие окна и не гарантирует, что выбранное окно создано именно этим запуском.

Для предсказуемого поведения указывайте цель у `move` и `run`. Если она отсутствует, реализация пробует использовать локализованную основу имени рабочего стола как цель или шаблон. Пропуск аргумента не означает текущий стол. В командах out/sole необязательное имя задаёт предпочтение или шаблон, а не обязательную точную цель.

## Справочник команд

### `run <ApplicationPath> [DesktopTarget]`

Запустить приложение, найти подходящее окно и перенести его на стол по номеру или имени. Добавьте `--create`, если целевой стол может отсутствовать.

```cmd
VDL run notepad.exe 2
VDL run notepad.exe Work --create --switch
VDL run "C:\Path\App.exe" "Office 2" --create --switch-first
```

В первом примере рабочий стол 2 уже должен существовать. Если цель определить не удалось, VDL сообщает об ошибке до запуска приложения с неопределённым назначением.

### `run-out <ApplicationPath> [DesktopTarget]`

Запустить приложение на наименее занятом столе, кроме стола, текущего на момент планирования цели. Основной критерий — число окон; предпочтение имени используется при равной занятости. `--create` разрешает создание цели, если другого стола нет.

```cmd
VDL run-out notepad.exe
VDL run-out notepad.exe Work --create --switch
```

### `run-sole <ApplicationPath> [DesktopTarget]`

Запустить приложение на пустом столе, кроме исходного текущего. Если подходящего пустого стола нет, создать стол с уникальным именем в пределах ограничения. Для этого запасного варианта `--create` не требуется.

```cmd
VDL run-sole notepad.exe
VDL run-sole notepad.exe Notes --switch
```

Необязательное имя отдаёт предпочтение подходящим пустым столам и задаёт шаблон при создании. Оно не требует создания нового стола, если уже есть пригодный пустой.

### `move [DesktopTarget]`

Перенести активное окно либо одно окно, подходящее под фильтры, на явно указанный стол.

```cmd
VDL move 2
VDL move Work --process notepad --create
VDL move "Office 2" --title-start "Total Commander" --create --switch
```

С `--all` без создания все выбранные окна используют одну цель. С `--all --create` VDL при планировании резервирует последовательные цели.

```cmd
VDL move Work --process notepad --all
```

### `move-all [DesktopTarget]`

Перенести все подходящие окна. Без `--create` они используют одну явную цель. С `--create` каждому окну выделяется отдельная последовательная цель: сначала может использоваться существующий стол, затем новые с именами `Notes 2`, `Notes 3` и далее.

```cmd
VDL move-all Work --process notepad
VDL move-all Notes --process notepad --create --verbose
```

Не запускайте массовый перенос без фильтров, если не собираетесь выбирать окна разных приложений. `--single` несовместим с `move-all`.

### `move-left` и `move-right`

Перенести окно относительно стола, на котором находится само выбранное окно, а не просто относительно стола запуска VDL. Значение `--steps` по умолчанию — 1.

Без фильтров выбора эти команды переносят активное окно на один стол:

```cmd
VDL move-right
VDL move-left
```

При вводе в активном окне CMD или Windows Terminal перенос самого терминала является ожидаемым действием. Например, `VDL move-right` со столом 1 в качестве исходного перенесёт терминал на стол 2, если тот существует. Команда `VDL move-left`, выполненная при активном терминале на столе 2, перенесёт его обратно на стол 1. В отличие от случайного совпадения заголовка в поиске с фильтром, здесь поиск по заголовку вообще не выполняется.

Чтобы явно переключиться на целевой стол вместе с окном:

```cmd
VDL move-right --switch
VDL move-left --switch
```

Для переноса другого приложения при вводе из терминала задайте фильтр процесса или заголовка:

```cmd
VDL move-left --title-start "Total Commander"
VDL move-left --process notepad --steps 2 --wrap
VDL move-right --process notepad --steps 3 --create
VDL move-right --process notepad --all --steps 1
```

Без `--wrap` или создания перенос останавливается на первом либо последнем столе. `--wrap` позволяет переходить между концами последовательности. `move-right --create` при необходимости добавляет столы. `move-left` не поддерживает создание. Обе команды не принимают позиционную цель и `--numeric-names`.

### `move-out [DesktopTarget]`

Перенести окно на наименее занятый стол, кроме его исходного. При массовом переносе запланированные назначения учитываются в занятости, чтобы распределять следующие окна между целями.

```cmd
VDL move-out --process chrome --all
VDL move-out Work --process notepad --create
```

Необязательное имя отдаёт предпочтение совпадающим столам при равной занятости. Если другого стола нет, `--create` разрешает создание цели.

### `move-sole [DesktopTarget]`

Перенести окно на пустой стол, кроме исходного. При массовом переносе каждое окно резервирует отдельный пустой стол. Если нужно, столы создаются в пределах ограничения.

```cmd
VDL move-sole --title-start "Total Commander"
VDL move-sole Notes --process notepad --all
```

Как и `run-sole`, эта команда может создать запасную цель без `--create`.

### `create [DesktopTarget]`

Создать один или несколько столов. Позиционный аргумент здесь задаёт шаблон имени, а не существующую цель для переноса окна. `--steps` определяет количество создаваемых столов.

```cmd
VDL create
VDL create Office --steps 3
VDL create "Office 4" --steps 2
VDL create --steps 2 --numeric-names
VDL create Work --steps 5 --max-desktops 100 --verbose
```

Без шаблона имена продолжают нумерацию от текущего числа столов с локализованной основой имени. Именованная последовательность начинается с `Office`, затем идёт `Office 2`, `Office 3` и так далее с пропуском занятых имён. `--numeric-names` использует числа без префикса. Создание само по себе не переключает фокус на новые столы.

### `clean`

Удалить столы без учитываемых видимых окон, сохранив как минимум один. Окна cloaked со стилем видимого окна учитываются. Стол, содержащий только окна без этого стиля, может считаться пустым.

```cmd
VDL clean
VDL clean --verbose
```

Очистка может удалить текущий стол, если он пуст. Для удаляемых столов запасным назначается первый сохранённый стол. Команда не принимает фильтры процессов или окон. `--clean` — отдельный параметр очистки после переноса, описанный ниже.

### `list`

Вывести позиции, имена и идентификаторы столов, отметив текущий. Подробный вывод также показывает количество окон.

```cmd
VDL list
VDL list --verbose
```

### `count`

Вывести число столов. Без подробного режима результат — только число.

```cmd
VDL count
VDL count --verbose
```

### `processes`

Вывести дерево процессов и связанные окна. Команда помогает узнать имена процессов, PID, дескрипторы и заголовки окон перед составлением фильтров.

```cmd
VDL processes
```

Команда не принимает `--verbose` и фильтры выбора окон.

### `profile save <file>` и `profile load <file>`

Сохранить или восстановить имена, порядок и обои рабочих столов. Формат и поведение восстановления описаны в разделе [Профили](#профили).

```cmd
VDL profile --help
VDL profile save workspace.json
VDL profile load workspace.json --verbose
VDL profile load workspace.json --max-desktops 100
```

`profile` — группа команд; для действия выберите `save` или `load`. У `save` нет параметров `--verbose` и `--max-desktops`, а `load` поддерживает оба. Файл для загрузки уже должен существовать.

## Справочник параметров

В примерах используются длинные имена параметров. Также перечислены псевдонимы с косой чертой для существующих сценариев. Все параметры запуска/переноса ниже доступны у `run`, `run-out`, `run-sole`, `move`, `move-all`, `move-left`, `move-right`, `move-out` и `move-sole`, если не указана более узкая область применения.

### Фильтры процессов и окон

| Параметр | Псевдонимы | Правило отбора | Пример |
| --- | --- | --- | --- |
| `--pid <id>` | `/ProcessId`, `/pid` | Один положительный PID; окна также должны пройти остальные фильтры. | `VDL move-left --pid 29184` |
| `--process <text>` | `/ProcessName`, `/p` | Подстрока имени исполняемого файла процесса. | `VDL move-left --process TOTALCMD64` |
| `--module <text>` | `/ModuleName`, `/mn` | Подстрока имени файла модуля. | `VDL move 2 --module notepad.exe` |
| `--path <text>` | `/ModulePath`, `/mp` | Подстрока пути исполняемого файла; маски не поддерживаются. Полный путь делает условие более точным. | `VDL move Work --path "C:\Tools\TOTALCMD64.EXE" --create` |
| `--title <text>` | `/WindowTitle`, `/t` | Подстрока в любой части заголовка. См. предупреждение о терминале выше. | `VDL move 2 --process notepad --title report` |
| `--title-start <text>` | `/WindowTitleStart`, `/ts` | Текст в начале заголовка. | `VDL move-left --title-start "Total Commander"` |
| `--title-regex <pattern>` | `/WindowTitleRegex`, `/tr` | Регулярное выражение .NET для заголовка. `^` привязывает начало выражения к началу строки. | `VDL move-left --title-regex "^Total Commander\b"` |
| `--empty` | `/Empty`, `/e` | Только окна с пустым заголовком или заголовком из пробельных символов. | `VDL move 2 --process MyApp --empty --all` |
| `--cloaked` | `/Cloaked`, `/cl` | Только окна с признаком cloaked от DWM, например находящиеся на другом столе. | `VDL move 1 --process notepad --cloaked --all` |
| `--main` | `/Main`, `/mo` | Только основные окна: верхнеуровневые, без владельца, со стилем видимого окна. | `VDL move 2 --process notepad --main` |
| `--invisible` | `/IncludeInvisible`, `/i` | Дополнительно включить окна без стиля видимости. | `VDL move 2 --process MyApp --invisible --all` |
| `--case` | `/CaseSensitive`, `/cs` | Учитывать регистр в фильтрах процессов, заголовков и имён столов. | `VDL move-left --title-start "Total Commander" --case` |

Фильтры имени процесса, модуля, пути и подстроки заголовка не проверяют точное равенство строк. Комбинируйте их для уточнения поиска. Если одновременно указаны имя модуля и путь, CLI проверяет согласованность имён файлов. Windows может запрещать перенос невидимых или ограниченных окон; включение в результаты поиска не гарантирует возможность переноса.

### Выбор одного или нескольких окон

| Параметр | Псевдонимы | Поведение | Пример |
| --- | --- | --- | --- |
| `--all` | `/All`, `/all` | Выбрать все совпадающие окна; подразумевается в `move-all`. | `VDL move-out --process chrome --all` |
| `--single` | `/SingleInstance`, `/si` | Отклонить несколько совпадающих окон вместо выбора одного. | `VDL move-left --process TOTALCMD64 --single` |

`--all` и `--single` взаимоисключающие. `--single` также запрещён для `move-all`. Без этих параметров перенос с фильтром выбирает одного полученного кандидата. При массовом поиске и проверке единственности VDL ждёт подходящие процессы без обычного раннего завершения по первому совпадению.

### Создание столов и относительный перенос

| Параметр | Псевдонимы | Доступность и поведение | Пример |
| --- | --- | --- | --- |
| `--create` | `/Create`, `/c` | Команды запуска/переноса, кроме `move-left`; разрешает недостающие цели. Команды sole уже имеют запасной вариант с созданием. | `VDL move Work --process notepad --create` |
| `--fill-gaps` | `/FillGaps`, `/fg` | Те же команды, что у `--create`; требует `--create`. Заполнить пропуски перед отсутствующей именованной целью. | `VDL move "Office 4" --process notepad --create --fill-gaps` |
| `--numeric-names` | `/NumericNames`, `/nn` | `create` и команды запуска/переноса с позиционным аргументом цели. Для запуска/переноса требует `--create`. Использовать числовые имена. | `VDL move 6 --process notepad --create --numeric-names` |
| `--steps <n>` | `/Steps`, `/ss` | `move-left`, `move-right`, `create`; положительное расстояние или число создаваемых столов. По умолчанию 1. | `VDL move-right --process notepad --steps 2` |
| `--wrap` | `/Wrap`, `/w` | `move-left` и `move-right`; переход между концами последовательности. Несовместим с `--create`. | `VDL move-left --process notepad --steps 2 --wrap` |
| `--max-desktops <n>` | `/MaxDesktops`, `/md` | Команды запуска/переноса, `create`, `profile load`; предел от 1 до 250 столов. По умолчанию 50. | `VDL create Work --steps 3 --max-desktops 100` |

Недостающая числовая цель требует создания всех физических позиций: если столов три, для `move 6 --create` нужны ещё три. Явное имя `"Office 4"` обычно создаётся само по себе; с `--fill-gaps` также создаются отсутствующие `Office`, `Office 2` и `Office 3`. Если цель уже существует, она используется напрямую: заполнение пропусков выполняется при разрешении отсутствующей цели.

`--max-desktops` ограничивает итоговое число столов, а не только число новых. Увеличение предела само по себе ничего не создаёт. Имена не меняют трактовку позиционного аргумента, состоящего только из цифр.

### Фокус и действия после переноса

| Параметр | Псевдонимы | Поведение | Пример |
| --- | --- | --- | --- |
| `--switch-first` | `/SwitchFirst`, `/swf` | Переключиться на цель до запуска или переноса. Вернуться на исходный стол, если не задан `--switch`. | `VDL run notepad.exe Work --create --switch-first` |
| `--switch` | `/Switch`, `/sw` | Оставить фокус на целевом столе после переноса. | `VDL move Work --process notepad --create --switch` |
| `--maximize` | `/Maximize`, `/mx` | Запросить полноразмерное представление окна после переноса; результат зависит от приложения. | `VDL move 2 --process notepad --maximize` |
| `--minimize` | `/Minimize`, `/mi` | Свернуть выбранное окно после переноса. | `VDL move 2 --process notepad --minimize` |
| `--clean` | `/Clean` | Удалить пустые столы после переноса. | `VDL move 2 --process notepad --all --clean` |

Параметры относятся к командам запуска/переноса. `--maximize` и `--minimize` взаимоисключающие. Сочетание `--switch-first --switch` допустимо и оставляет фокус на цели. При нескольких целях итоговый фокус может перейти на последнюю обработанную. Очистка может изменить позиции столов и удалить опустевший текущий стол.

### Режим поиска и интервалы

Когда VDL ищет окна для переноса, приложение может ещё запускаться, создавать основное окно или заменять заставку. Эти параметры определяют, сколько времени VDL ищет совпадения и как проверяет, что набор подходящих окон перестал меняться. Все интервалы задаются в миллисекундах: `1000` — одна секунда.

**Тайм-аут — общий лимит времени поиска.** `--timeout` (по умолчанию `5000`, то есть пять секунд) ограничивает весь поиск, включая повторные попытки при отсутствии совпадений и проверку стабильности. Это максимальное время ожидания: успешный поиск может закончиться раньше. При исчерпании лимита VDL может использовать уже найденные стабильные совпадения; если их нет, стабильного окна для переноса тоже нет. Увеличение значения помогает приложениям, окна которых появляются медленно. Тайм-аут не завершает запущенное приложение и не ограничивает время всей команды VDL: запуск, начальная задержка и сам перенос не входят в этот лимит поиска.

**Стабильность — сколько времени кандидат должен оставаться неизменным.** `--stability` (по умолчанию `500`) даёт каждому процессу-кандидату время на создание или замену окон. По свежим снимкам окон VDL проверяет, что у лучшего подходящего окна сохраняется тот же дескриптор, а количество подходящих окон этого процесса не меняется. Изменение запускает отсчёт стабильности для этого процесса заново; исчезновение всех совпадений сбрасывает его. Для основного окна нужен заданный интервал, для неосновного — на 50% больше (`750` мс при значении по умолчанию). Увеличение интервала помогает не выбрать временное окно запуска, но замедляет поиск. Проверяются дескриптор и количество окон, поэтому стабильность не означает, что документ полностью загружен или заголовок больше не изменится. Даже при `--stability 0` требуется последующее свежее наблюдение, подтверждающее кандидата. Проверки выполняются периодически, поэтому момент завершения не рассчитывается с точностью до миллисекунды.

**Задержка — пауза перед поиском.** `--delay` (по умолчанию `0`) один раз приостанавливает работу перед выбором окон. В команде `run` приложение запускается до этой паузы и получает дополнительное время на запуск. Пауза не расходует тайм-аут и не засчитывается как подтверждение стабильности. Используйте её, если приложению заведомо нужно время перед началом поиска; увеличивайте тайм-аут, если хотите начать поиск сразу и ждать по необходимости.

Например, `--delay 2000 --timeout 10000 --stability 500` означает: подождать две секунды, затем искать до десяти секунд, проверяя стабильность в пределах этих десяти секунд. Ещё полсекунды после тайм-аута не добавляются. Найденное совпадение может завершить поиск раньше, а запуск и перенос могут увеличить общее время команды.

**Режимы поиска — когда стабильных результатов уже достаточно.** `--mode` выбирает правило завершения; во всех режимах действуют заданные фильтры и проверка стабильности:

- **Fast** разрешает завершить поиск, как только у любого процесса-кандидата найдены стабильные подходящие окна. Подходит для точного фильтра, когда важна скорость.
- **Balanced** (по умолчанию) разрешает досрочное завершение, когда у процесса-кандидата стабилизировалось подходящее основное окно. Режим даёт основным окнам шанс перед завершением по другому типу окна, но также может закончить поиск, когда все процессы-кандидаты завершили свои проверки. Он не требует фильтра `--main`; добавьте `--main`, если допустимы только основные окна.
- **Thorough** не останавливает поиск досрочно из-за готовности одного кандидата. Он ждёт завершения проверок стабильности у обнаруженных процессов-кандидатов либо исчерпания лимита времени. Если все кандидаты завершили проверки, поиск может закончиться до тайм-аута; обнаружение окон, которые появятся позже, не гарантируется.

`--all` и `--single` отключают досрочное завершение в Fast и Balanced, чтобы поиск мог собрать результаты по процессам-кандидатам. Режим определяет момент завершения поиска, но не устраняет неоднозначность фильтра. Например, заголовок терминала с текстом введённой команды тоже может соответствовать `--title Commander`; используйте более точный фильтр, например `--title-start "Total Commander"`.

Тайм-аут, стабильность и режим относятся к поиску подходящих окон в командах запуска/переноса. Обычные `VDL move-left` и `VDL move-right` выбирают активное окно напрямую, без такого поиска. Задержка по-прежнему действует перед выбором активного окна.

| Параметр | Псевдонимы | Значение по умолчанию и ограничения | Пример |
| --- | --- | --- | --- |
| `--mode <Fast\|Balanced\|Thorough>` | `/Mode`, `/m` | Balanced. Определяет, когда поиск может вернуть стабильные совпадения. | `VDL move-left --title-start "Total Commander" --mode Thorough` |
| `--timeout <ms>` | `/MaxTimeout`, `/mt` | 5000; диапазон 100–300000. Общий лимит времени поиска и стабилизации. | `VDL run "C:\Path\SlowApp.exe" Work --create --timeout 15000` |
| `--stability <ms>` | `/StabilityTime`, `/st` | 500; диапазон 0–30000, не больше тайм-аута. | `VDL move 2 --process MyApp --stability 1000 --timeout 10000` |
| `--delay <ms>` | `/Delay`, `/d` | 0; диапазон 0–300000. Пауза перед поиском окна. | `VDL run "C:\Path\SlowApp.exe" Work --create --delay 2000` |

Примеры выбора каждого режима:

```cmd
VDL move-left --title-start "Total Commander" --mode Fast
VDL move-left --title-start "Total Commander" --mode Balanced
VDL move-left --title-start "Total Commander" --mode Thorough
```

### Аргументы запуска и способ выполнения

| Параметр | Псевдонимы | Доступность и поведение | Пример |
| --- | --- | --- | --- |
| `--args <arguments...>` | `/Arguments`, `/a` | Только команды запуска; передать аргументы приложению. | `VDL run notepad.exe Work --create --args "C:\Notes\todo.txt"` |
| `--no-shell` | `/NoShell`, `/ns` | Только команды запуска; отключить `UseShellExecute` и запустить напрямую. | `VDL run "C:\Path\App.exe" Work --create --no-shell` |

По умолчанию используется запуск через оболочку. `--no-shell` полезен с путями к исполняемым файлам и для обхода системных псевдонимов, но у VDL нет параметров перенаправления ввода/вывода приложения. При прямом запуске, если путь содержит существующий каталог, VDL использует его в качестве рабочего.

| --- | --- | --- | --- |
| `--verbose` | `/Verbose`, `/v` | Запуск/перенос, `create`, `clean`, `list`, `count`, `profile load`; подробности соответствующей операции. | `VDL move-left --title-start "Total Commander" --verbose` |
| `--help` | Встроенные `-h`, `-?`; другие псевдонимы см. в справке команды. | Показать общую справку или справку команды. | `VDL move-left --help` |

VDL --help

## Аргументы приложений и кавычки

В командах запуска отделяйте параметры VDL от аргументов приложения с помощью `--`, особенно если у приложения есть собственные параметры:

```cmd
VDL run "C:\Path\App.exe" Work --create -- --new-window "C:\Notes\todo.txt"
```

Всё после `--` передаётся приложению. Параметры VDL ставьте перед разделителем. Альтернатива — `--args`:

```cmd
VDL run notepad.exe Work --create --args "C:\Notes\todo.txt"
```

Предпочитайте один способ передачи аргументов в одном вызове. Если у `--args` есть значения, они имеют приоритет над нераспознанными завершающими аргументами. Команда запуска может принимать нераспознанные токены как аргументы приложения; поэтому опечатка в параметре VDL иногда приводит к его передаче приложению, а не к ожидаемой ошибке. Для диагностики используйте `--verbose`.

Заключайте в кавычки пути, имена столов и фильтры с пробелами. Разбор аргументов Windows может быть неожиданным, когда аргумент в кавычках заканчивается обратной косой чертой: она способна экранировать закрывающую кавычку. Для передачи буквальной завершающей косой черты через этот механизм удвойте её:

```cmd
VDL run "C:\Path\App.exe" Work --create -- "C:\Folder With Spaces\\"
```

Правила также зависят от оболочки. В примерах используются обычные двойные кавычки, подходящие для CMD; PowerShell сначала выполняет собственный разбор. В подробном отчёте об аргументах можно проверить восстановленную строку запуска.

## Профили

Профиль хранит конфигурацию рабочих столов: имена, порядок и пути к обоям. Он не хранит сеансы приложений, команды запуска, позиции окон или назначения окон столам.

```cmd
VDL profile save workspace.json
VDL profile load workspace.json --verbose
```

Минимальный профиль выглядит так:

```json
[
  { "Name": "Work", "WallpaperPath": null, "Children": [] },
  { "Name": "Notes", "WallpaperPath": null, "Children": [] }
]
```

Чтение также поддерживает старые вложенные структуры `Children`, разворачивая их по порядку. В файле должен быть хотя бы один стол без повторяющихся имён. Столы без сохранённых имён записываются с фактическими локализованными именами, например `Desktop 1`.

При восстановлении сначала используются столы с совпадающими именами, затем остальные по позиции; при необходимости создаются новые. Лишние управляемые столы удаляются, а их окна переходят на первый сохранённый. Поэтому загрузка профиля может косвенно переместить окна, хотя назначения приложений она не восстанавливает.

Каталог назначения при сохранении уже должен существовать. Существующий файл перезаписывается. Пути к обоям должны быть доступны на компьютере загрузки: изображения не копируются в профиль. Значение `null` не запрашивает изменение обоев.

## Рабочее окружение при входе через Планировщик заданий

При желании можно использовать Планировщик заданий Windows, чтобы при входе в систему запускать приложения и размещать их окна на выбранных столах. В каждом действии укажите **непосредственный запуск VDL.exe**, а команду и аргументы сохраните в свойствах задачи. Внешний файл `.cmd` или `.bat` и промежуточная командная оболочка для этого не используются.

Например, для запуска Блокнота на столе `Work` откройте **Планировщик заданий**, выберите **Создать задачу** и настройте:

1. **Общие:** укажите свою учётную запись Windows и выберите **Выполнять только для вошедших в систему пользователей**.
2. **Триггеры:** добавьте **При входе в систему** для этой учётной записи. Необязательная задержка около 30 секунд даст оболочке рабочего стола время на запуск.
3. **Действия:** добавьте **Запуск программы** и задайте следующие значения, заменив пути на свои:

| Свойство действия | Значение |
| --- | --- |
| **Программа или сценарий** | `C:\Tools\VDL\VDL.exe` |
| **Рабочая папка** | `C:\Tools\VDL` |

В поле **Добавить аргументы** укажите только команду VDL и её аргументы:

```text
run "C:\Windows\System32\notepad.exe" Work --create --process notepad --main --timeout 15000
```

Сохраните задачу и проверьте её командой **Выполнить**, находясь в своей пользовательской сессии. VDL запустит Блокнот и перенесёт его подходящее основное окно на `Work`, создав стол при необходимости.

Для других приложений добавьте в ту же задачу дополнительные действия **Запуск программы**. Каждое действие напрямую запускает `VDL.exe` и имеет собственное значение поля **Добавить аргументы**. Например, второе действие может запускать Firefox на столе `Browsing`:

```text
run "C:\Program Files\Mozilla Firefox\firefox.exe" Browsing --create --process firefox --main --timeout 15000 -- --new-window "https://example.com"
```

Замените Firefox приложением, установленным у вас. Путь к исполняемому файлу задавайте в поле **Программа или сценарий**, аргументы — в поле **Добавить аргументы**. Несколько действий одной задачи Планировщик выполняет последовательно; расположите их в нужном порядке. Подробнее — в [документации Microsoft о действиях задач](https://learn.microsoft.com/en-us/windows/win32/taskschd/task-actions).

Для работы с графическими окнами используйте триггер **При входе в систему**. Задача, работающая без вошедшего пользователя, может выполняться вне интерактивного рабочего стола и не сможет надёжно расположить видимые вам окна. Подробнее — в [документации Microsoft о контекстах безопасности Планировщика заданий](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks).

Приложения могут использовать существующие процессы или окна: повторный запуск задачи не гарантирует ещё одного независимого окна или полностью одинакового окружения. При необходимости уточните аргументы приложений и фильтры окон. Профили восстанавливают только структуру столов; запуск приложений задаётся действиями задачи. VDL не восстанавливает сеансы приложений и сохранённую геометрию окон.

## Устранение неполадок

| Симптом | Причина и дальнейшие действия |
| --- | --- |
| Вместо приложения переносится терминал. | Посмотрите заголовок в отчёте. Условие поиска может содержаться в командной строке, включённой CMD в заголовок. Используйте `--title-start` или `--process`: кавычки вокруг подстроки не устраняют неоднозначность. |
| Выбирается другое окно приложения. | Несколько окон могут проходить фильтр подстроки. Объедините фильтр процесса и заголовка либо укажите актуальный PID. `--single` отклоняет несколько совпадений. |
| Подходящее окно не найдено. | Проверьте текущие заголовки и процессы через `VDL processes`. Начальная фраза должна совпадать с началом заголовка, кроме игнорируемого по умолчанию регистра. Проверьте `--main`, `--empty` и ограничения видимости. |
| Окно медленного приложения не успевает стабилизироваться. | Увеличьте `--timeout`, при необходимости задайте `--delay` или попробуйте Fast/Balanced после уточнения фильтра. |
| Окно другого стола помечено cloaked. | Это нормально для многих окон других столов. `--cloaked` выбирает только такие окна; `--invisible` относится к другому признаку — стилю видимого окна. |
| Относительный перенос ничего не меняет. | Возможно, окно уже на первом или последнем столе. Используйте `--wrap` либо `move-right --create` для расширения последовательности. Также проверьте выбранные дескриптор и заголовок. |
| Невозможно определить цель. | Посмотрите `VDL list`, укажите явную цель и добавьте `--create`, если отсутствующий стол нужно создать. |
| Создание отклонено. | Проверьте общее число столов и `--max-desktops`: заполнение пропусков может потребовать нескольких новых столов. |
| Отказано в доступе или окно исчезает во время переноса. | Окно может закрыться, сменить дескриптор или иметь ограничения. Проверьте права и выберите актуальное окно приложения. |
| Профиль не открывает приложения заново. | Профиль восстанавливает только структуру столов. Для запуска используйте отдельные команды run. |

В отчёте дескриптор и сохранённый заголовок печатаются перед попыткой физического переноса. После строки выбора может появиться ошибка: сама строка не подтверждает успех. `Done` и итоговые сообщения описывают обработанные выбранные окна, но не подтверждают независимо, что заголовок соответствовал вашему намерению.

Нет общедоступного параметра пробного запуска или универсальной команды отмены. Ошибки планирования не меняют Windows, но сбой после начала синхрониронизации может оставить уже выполненные переносы, изменения имён и обоев. При очистке удаляются только пустые вновь созданные столы. Работа зависит от версии Windows и доступного механизма виртуальных рабочих столов.

## Сборка и проверка

Проект предназначен для .NET 10 под Windows. Зависимости `Slions.VirtualDesktop`, `System.CommandLine` и Polly подключаются через NuGet. Лицензии и уведомления собраны в [THIRD-PARTY-NOTICES.txt](THIRD-PARTY-NOTICES.txt), исходные копии сохранены в [`licenses/`](licenses/).

```powershell
dotnet build VDL.slnx
dotnet build VDL.slnx -c Release
dotnet publish VDL.csproj -c Release -p:PublishProfile=Standalone
dotnet run --project Tests/VDL.Tests.csproj
dotnet run --no-launch-profile -- --help
```

При запуске CLI из каталога проекта используйте `--no-launch-profile`: профиль запуска IDE может задавать собственные аргументы. Результаты сборки находятся в `bin/Debug/net10.0-windows10.0.19041.0/` либо соответствующем каталоге Release.

Набор регрессионных проверок охватывает разбор аргументов, диспетчеризацию и планирование в памяти без переноса настоящих окон. Необязательная интеграционная проверка только для чтения ищет реальные окна через рабочий код поиска и стабилизации:

```powershell
dotnet run --project Tests/VDL.Tests.csproj -- --inspect-title-start "Total Commander"
```

### Измерения опроса без изменения окон

**Только для разработки.** Этот инструмент измерений предназначен для разработчиков, оценивающих производительность опроса и изменения кэша. Для установки, настройки и обычного использования VDL запускать его не требуется.

Запустите измерения в конфигурации Release:

```powershell
dotnet run --project Tests/VDL.Tests.csproj -c Release -- --measure-polling output/measurements/polling.json
```

Проверка измеряет сбор окон и процессов, выделение памяти и стоимость попадания в кэш, независимый и общий сбор с 1/8/16 читателями, фиксированную и адаптивную свежесть в синтетическом поиске стабильности. Последний поиск использует рабочий путь обнаружения без переноса окна. JSON-отчёт содержит сведения о машине, количество измерений, времена операций, число сборов и запросов, длительность поиска.

Синтетические случаи добавляют блокирующие задержки сбора 5/20/50 мс. Фактическая задержка может быть больше из-за планирования Windows; это отражается в измеренном времени сбора. Такие случаи моделируют дорогие наблюдения, но не целиком медленный компьютер и не его загрузку процессора. Для представительных результатов запускайте тот же инструмент на старых компьютерах. Короткие пробные запуски показывают компромиссы, но не дают статистически надёжных гарантий производительности.
